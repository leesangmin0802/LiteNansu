# 실험 방법과 해석

## 측정 조건

속도 실험은 시드를 고정하고 두 생성기를 예열한 다음 실행 순서를 번갈아 바꿉니다. 32비트 정수, 0~1 실수, 0~99 범위 정수를 별도로 측정합니다. 결과에는 각 회차 시간과 중앙값, 초당 백만 개 처리량을 저장합니다. 초기화 시간과 실제 힙 메모리 사용량은 측정하지 않습니다.

Node 기본값은 속도 회차당 1천만 개·11회, 품질 시드당 100만 개입니다. 입력 시드와 0, 1, 4294967295를 중복 없이 검사합니다. HTML 기본값은 회차당 100만 개·5회, 품질 100만 개이며 입력한 시드 하나를 검사합니다. 두 환경의 속도 수치를 직접 혼합하지 마세요.

품질 검사는 먼저 `nextUint32()`로 표본을 생성합니다. 그 다음 같은 생성기 상태에서 `int(6)`를 별도로 표본 수만큼 호출해 주사위 빈도를 계산합니다. 산점도는 처음 최대 2,048개 출력을 겹치지 않는 두 개씩 묶고, 흐름 차트는 처음 64개만 표시합니다. 전체 통계를 계산하는 표본 수와 미리보기 점 수는 다릅니다.

## 품질 지표

| 지표 | 기대와 해석 |
|---|---|
| 출력 평균 | 0.5 부근. 표본 오차가 발생합니다. |
| 상·하위 바이트 빈도 | 256개 구간. χ² 자유도 255. |
| 비트 Z 점수 | 1 빈도의 표준화 편차. 0 부근. ±3 참고선은 합격선이 아닙니다. |
| 간격별 상관계수 | 1·2·16·64 간격의 피어슨 상관. 0 부근. |
| 주사위 빈도 | 6개 구간. χ² 자유도 5. |
| 원주율 추정 | 인접한 출력 두 개를 좌표로 사용. 3.14159… 부근. |

차트의 바이트 빈도는 `(관측 빈도 / 기대 빈도 − 1) × 100`으로 표시합니다. 상위·하위 차트는 같은 세로축 범위를 씁니다. 통계의 p값이나 자동 합격 판정은 제공하지 않습니다. 특히 적은 표본에서는 구간별 기대 빈도가 작아 χ² 근사의 해석에 주의가 필요합니다.

여러 시드·비트·지표를 검사하면 우연한 극단값이 생길 수 있습니다. 다른 시드와 더 큰 표본에서도 같은 결함이 반복되는지 확인하세요. 산점도, 평균, 원주율 하나만으로 생성기 품질을 판단하지 마세요.

## 재현

```sh
npm run experiment -- --samples 1000000 --count 10000000 --rounds 11 --seed 12345
node src/export.ts litenansu 12345 10000000 > stream.bin
```

`results/report.json`은 전체 결과이며 `results/summary.md`는 요약입니다. 저장소에 포함된 결과는 Node v24.22.1, macOS arm64에서 측정한 예시입니다. 같은 시드의 난수 출력과 통계는 재현할 수 있지만 실행 시간은 기기·브라우저·시스템 부하·시계 해상도에 따라 달라집니다.

원시 출력은 uint32 little-endian입니다. 전문 통계 검사를 위해 PractRand나 TestU01 등에 연결할 수 있지만 해당 도구는 이 저장소에 포함하지 않았고 기본 실험으로 실행하지 않습니다.

## 범위와 한계

암호 용도로 사용하지 않습니다. 이 진단은 긴 주기, 독립 스트림, 모든 형태의 상관 부재를 증명하지 않습니다. LiteNansu는 32비트 시드를 받으므로 생성자에서 선택할 수 있는 초기 상태는 최대 2³²개입니다. 128비트 상태 전체를 시드 하나로 탐색하지 않습니다. 서로 다른 시드를 사용해도 난수열이 겹치지 않는다는 보장은 없습니다.
